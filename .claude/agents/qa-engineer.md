## Mission

### 1. Test helpers: `server/test/helpers/`

- `fixtures.ts`: a small hand-built course (pack plus questions) that satisfies the Zod schemas: 2 or 3 rooms, 3 concepts, 2 misconceptions per concept, key points with evidence, and enough questions of every type for room draws and a 10-question boss, including multi-concept questions and at least one question with a deterministic wrong-answer path per misconception. Validate it with `CoursePackSchema` and `QuestionSchema` in a test.
- `fakes.ts`: a scripted fake `GameplayTasks` (you control what the student answers, what the review returns and whether an answer resolves), a fake `Retriever`, a fixed clock you can advance, and an RNG you can script (for example always 0 or always 0.99) alongside `createRng`.
- `leaks.ts`: `findHiddenKeys(value): string[]`, a recursive scan that returns the path of every forbidden key. Forbidden everywhere: `hidden`, `misconceptionId`, `misconceptionIds`, `correctIndex`, `correctIndexes`, `correctValue`, `acceptedAnswers`, `wrongAnswers`, `wrongOrders`, `correctOrder`, `wrongMisconceptionId`, `solution`, `workedSteps`, `rubric`, `modelAnswer`, `targetedMap`, `rngSeed`, `rngState`, `embedding`, `keyPoints`, `misconceptions`, `materialItems`. Note that `correctAnswer` and `explanation` are allowed in a turn result for a question that has been answered, and `costlyMisconceptions` (with `beliefStatement` and `correction`) is allowed in results.
- `app.ts`: `startTestApp(env?, options?)` that builds the real app with `createContainer({ env: { LLM_PROVIDER: 'mock', DEBUG: 'true', ...env }, seed, clock })` and `buildApp`, and returns helpers that call `app.inject` and parse JSON.

### 2. Vitest tests from the spec: `server/test/*.test.ts`

Engine-level tests import `engine` from `server/src/engine` and drive it with your fakes and fixture. HTTP-level tests go through `startTestApp`. Cover:

- **Scoring math and grade thresholds**: health per wrong answer with 10 and 6 boss questions, rounding, the letter at each threshold boundary, `metTarget`, custom `GRADE_THRESHOLDS`.
- **Boss composition**: at least `k` targeted questions when misconceptions are active (`k = min(active, floor(N × 0.5))`), every concept in scope covered, multi-concept questions preferred, no duplicates, only verified questions, only questions inside the scope.
- **Learning**: a skip makes the misconception active and puts its belief line in the notebook as a plain bullet with no label; an answer resolves the misconception and adds the corrective note; a failed answer behaves like a skip; re-teaching resolves an active misconception and replaces the belief line; a stated misconception becomes active; open questions are auto-skipped at ready; at most `MAX_STUDENT_QUESTIONS`.
- **Room**: hearts reset on retry (Option B); retries draw fresh questions first; no repeats within an attempt; fail at 0 hearts; the reasoning trace on fail; rooms never change the grade; the notebook survives a retry.
- **Grading for every question type** through core/grading.ts, including numeric tolerance (absolute and relative) and wrong-answer mapping for each type. Keep these complementary to `core.test.ts` rather than copies of it.
- **The grounding rule**: a correct answer with no valid citation counts as wrong with reason `not in my notes`.
- **Time budget**: the formula for every type and step kind, clamping, the material-hint override, calibration after 5 solves, and the untimed mode (`HELP_ME_TIMED=false` gives `deadline: null` and a late answer is impossible).
- **"Help me!"**: correct (no damage, the `Teacher showed me:` note), wrong (damage), late (damage even with the right answer), the caps, never `free_response`, the time multiplier, the solve time recorded in stats.
- **Coverage invariants hold on both sample packs**: load `samples/cache/seasons.json` and `samples/cache/binary-search.json` (parse with `CourseFixtureSchema`) and check SPEC 4.4 yourself, independently of the ingest module's own checker: every key point has a question, every misconception has a wrong-answer path, every room has at least `ROOM_QUESTIONS × ROOM_POOL_FACTOR` questions inside the room, at least `ceil(BOSS_QUESTIONS / 2)` multi-concept questions, every question verified, every evidence quote present in its chunk (whitespace-normalized).
- **Provenance priority**: in both sample packs every convertible material item has a `verbatim` question, and `generated` questions exist only for gaps. Also drive `runIngest` from `server/src/ingest` with the mock tasks and assert that verbatim questions are produced before anything is generated.
- **Phase guards**: every action in every wrong phase returns 409 with `{ error: { code: 'wrong_phase' } }`; an unready room returns 425; unknown ids return 404; bad bodies return 400.
- **No hidden-field leakage**: play a whole gauntlet over HTTP and run `findHiddenKeys` on every response body of every public endpoint (`/courses/:id`, `/runs`, `/runs/:id`, `/teach`, `/answer`, `/skip`, `/ready`, `/turn`, `/help`, `/retry`, `/continue`, `/results`). Also check that `/debug` returns 404 when `DEBUG=false` and the full state when it is true.
- **Skipping raises boss targeting**: the same seeded run with and without a skipped question; the skipped misconception's question is in the boss and it shows up in `costlyMisconceptions`.
- **Edge cases**: double submits (a second `/help` for the same event, a second answer to the same student question), an expired "Help me!" followed by `/turn`, and `/turn` after the fight has ended (idempotent summary).

### 3. End-to-end script: `scripts/e2e.ts` (`npm run e2e`, already wired)

Plays a full gauntlet against the real API with mocks and prints a readable transcript.

- Start the app in-process on a free port (`createContainer({ env: { LLM_PROVIDER: 'mock', DEBUG: 'true' }, seed: 42 })`, `buildApp`, `app.listen({ port: 0 })`) and drive it only through `createApiClient` from `@top/shared/api-client`. Accept `--url <base>` to target an already running server instead, and `--sample <name>` (default `seasons`).
- It is a "teacher bot". It reads the hidden course data from `getDebug` (key points, misconceptions and their corrections, answer keys) only to decide what to type, the way a human teacher who knows the subject would.
- Script: seed the sample → create a run (target B) → **room 1, first attempt: teach one vague sentence**, press ready, and play turns until the room fails; print the reasoning trace → **retry** → teach properly (the room's key point statements as sentences), **skip one student question on purpose**, answer the others with the misconception's correction, ready, and play until the room passes → for each later room teach properly and answer every question → boss → results.
- Answer every "Help me!" event correctly using the key from the debug payload.
- Print the notebook after each learning phase, each turn in one or two lines, and the final results including the costly misconceptions.
- Finish with assertions and a non-zero exit code if any fails: the first attempt of room 1 failed and the retry passed; the skipped misconception is in `results.costlyMisconceptions`; no response contained a hidden key; the run ended in phase `results`.
